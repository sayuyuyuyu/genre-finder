# 使い方

「これ何ジャンル？」は、ジャンルがわからない曲を3つの入口から調べるアプリです。公開版の URL は <https://genre.slytxt.dev> です（<https://genre-finder.pages.dev> でも開けます）。ローカルで動かす手順は [README](../README.md#ローカルで動かす) にあります。

## 曲名から調べる

1. 入力欄に曲名を入れます。「曲名 アーティスト」の形でも構いません。
2. 候補一覧から、調べたい曲を選びます。
3. 判定結果が表示されます。

候補が多すぎるときは、アーティスト名を添えると絞れます。カタカナ表記で出てこない曲は、英語表記や原題でも試してください。`feat.` やリミックス表記がある曲は、候補一覧から目的のバージョンを選びます。

## リンクから調べる

曲のページの URL を入力欄に貼ると、曲名とアーティスト名を解決して候補を出します。対応している URL は次のとおりです。

| サービス | 対応する URL |
| --- | --- |
| Spotify | `open.spotify.com/track/...`（`open.spotify.com/intl-ja/track/...` も可） |
| YouTube | `youtube.com/watch?v=...`、`youtu.be/...`、`youtube.com/shorts/...` |
| Apple Music | `music.apple.com/.../song/...`、アルバム URL に `?i=` が付いた曲ページ |
| Deezer | `deezer.com/track/...` |

1. リンクを入力欄に貼ります。
2. 曲名とアーティスト名が解決され、候補一覧が出ます。
3. 候補を選ぶと判定に進みます。

Spotify のアルバム・プレイリスト、YouTube のチャンネルやライブ配信、Apple Music のアルバム全体の URL は解決しません。曲のページの URL を使ってください。

Spotify のリンクは、`SPOTIFY_CLIENT_ID` と `SPOTIFY_CLIENT_SECRET` が設定されていれば Spotify API で正確に解決します。設定が無い場合は oEmbed と埋め込みページから曲名とアーティスト名を推定するため、表記がずれることがあります。

## 音声ファイルから調べる

音声ファイルを画面にドラッグ&ドロップするか、ファイル選択から選びます。ファイルのタグ（タイトル・アーティスト・アルバム）を読み取り、その内容で検索します。タグが無い場合は、ファイル名から「アーティスト - 曲名」の形を推測します。

音声データそのものは送信しません。ブラウザ内でタグを読み、曲名とアーティスト名だけを検索に使います。

タグを読めない形式や、ファイル名が「アーティスト - 曲名」になっていないファイルは、候補が出ないことがあります。その場合は曲名を手入力してください。

## 結果の読み方

### 判定結果の共有

判定画面の URL は `?t=曲名&a=アーティスト` の形式になります。コピーして渡すと、開いた人の画面でもその曲の判定が始まります。

### RANDOM（おまかせ）

トップページの `EXAMPLES` の右にある `RANDOM` を押すと、ジャンルも時代もバラバラな曲から1曲選んで判定します。直前と同じ曲は選ばれません。

### RECENT（履歴）

判定した曲は、トップページ下部の `RECENT` に最大6件残ります（ブラウザ内に保存）。押すとその曲をもう一度判定します。`CLEAR` で消せます。

2曲以上たまると `PLAY DATA` に調べたジャンルの集計（例: `J-POP 2 / CHIPTUNE 1`）が出ます。

### 曲の候補一覧

候補はIIDXの選曲リスト風に、曲番号・アートワーク・曲名・アーティスト・ジャンル（全大文字）・曲時間が並びます。候補を選ぶと、その曲について各ソースの証拠を集めて判定します。

### ジャンルと信頼度

判定結果の上部に、大きな全大文字のジャンル名（arcade 表記）が出ます。その下に日本語名と大分類、信頼度の `LV.xx`（1〜12 の目盛り）と `%` が並びます。`LV` は目盛り、`%` が集めた証拠のうちそのジャンルを支持した割合です。

#### WORK（ゲーム作品名）

ゲーム音楽と判定できたとき、ジャンル名の下に `WORK / UNDERTALE` のように作品名が出ます。作品名は曲名・アルバム名・アーティスト名から検出します。

#### PREVIEW（30秒試聴）

曲情報の下の丸いボタンで、その曲の30秒プレビューを再生します。リングが再生位置、`STOP` で停止します。プレビュー音源が無い曲ではボタンが出ません。再生できない場合は `NO AUDIO` と表示します。

#### SPECTRUM（マルチジャンル）

1曲を1ジャンルに決めつけず、候補の混ざり具合を棒で表示します。`J-POP 70 / DANCE POP 57 / ANIME 21` のように並び、1行目が第一候補です。

行を押すと、そのジャンルを支持した根拠だけが `DATA FEED` に残ります（`FILTER ON`）。もう一度押すと全体に戻ります。

| 表示 | 信頼度 | 意味 |
| --- | --- | --- |
| 高 | 0.6 以上 | 複数のソースが同じ方向を指している |
| 中 | 0.35 以上 0.6 未満 | 支持はあるが、対立する証拠や不足がある |
| 低 | 0 より大きい | 証拠が少ない、またはソース間で割れている |
| 判定不能 | 証拠なし | どのソースも分類できなかった |

信頼度は「そのジャンルが正しい確率」ではありません。複数ソースの一致度です。高いほど根拠は揃っていますが、ジャンル名そのものが音楽的に正しいかを保証するものではありません。

### DATA FEED（根拠）

判定に使った証拠が、重みの大きい順に最大6件並びます。各行にはソース名、ソースが返した生のラベル（`J-Pop`、`french house`、`ダンス` など）、重み（0〜1）が出ます。カーソルを合わせると補足（投票数など）が出ます。重みはソースの種類と、MusicBrainz / Last.fm では投票数で決まります。詳しい計算は [ARCHITECTURE.md](ARCHITECTURE.md#信頼度の計算) にあります。

### 細分類タグ

分類表に載っていないタグは「細分類タグ」として表示します。`shibuya-kei` や `french house` のように、ジャンル名より細かい情報です。ジャンル名には昇格させず、参考情報として並べます。

### 関連ジャンル

判定したジャンルの近いジャンルを表示します。聴き比べの手がかりに使ってください。

### 注意書きと失敗したソース

判定に使ったソースの限界が「注意書き」に出ます。たとえば「iTunes はポップとだけ分類しています」「MusicBrainz にタグが付いていません」などです。外部 API に接続できなかったソースも別に表示します。失敗したソースがあっても、残りのソースで判定します。

### 外部リンク

Apple Music、Spotify、YouTube で同じ曲を検索するリンクがあります。

## うまく判定できないとき

| 症状 | 原因の例 | 対処 |
| --- | --- | --- |
| 候補が出ない | 表記ゆれ、配信されていない曲、インディーズ | 英語表記や原題で試す。アーティスト名を添える。リンクを貼る |
| 目的と違う曲が候補の上位に出る | 同名曲、カバー、リミックス | 候補一覧から正しい曲を選ぶ。アーティスト名を添える |
| 信頼度が低い | タグが少ない、ソース間でジャンルが割れている | 根拠リストを見る。別の入口（リンクや音声ファイル）で試す |
| 判定不能になる | どのソースにもジャンル・タグが無い | アーティスト名を添えて再検索する。リンクから試す |
| リンクが解決されない | 対応外の URL、非公開動画、URL の取り違え | 曲のページの URL を確認する。曲名で検索する |
| 音声ファイルのタグが読めない | タグの無い形式、ファイル名が曲名になっていない | 曲名を手入力する |
| Last.fm や Spotify の根拠が出ない | シークレット未設定 | 設定するか、他のソースの根拠だけで判断する |
| 「一部の情報源に接続できませんでした」と出る | 外部 API の停止、レート制限、タイムアウト | 時間を置いて再実行する |

## よくある質問

**ジャンル判定に機械学習を使っていますか。**

使っていません。iTunes、Deezer、MusicBrainz、Last.fm が返す分類とタグを、ソースごとの重みで集計しています。判定の根拠はすべて画面に出ます。

**音声ファイルはサーバーに送られますか。**

送りません。ブラウザ内でタグを読み取り、曲名とアーティスト名だけを検索に使います。

**オフラインで使えますか。**

使えません。判定のたびに外部 API を呼びます。

**表示されたジャンルが自分の感覚と違います。**

ジャンルは境界が曖昧で、ソースごとに分類も違います。根拠リストを見て、どのソースがそのジャンルを支持したかを確認してください。信頼度が低い場合は、ソース間で見解が割れています。

**データはどのくらいの頻度で更新されますか。**

検索結果は10分、判定結果とリンク解決は1時間、Cloudflare 側でキャッシュします。それより前のデータは、各サービスのデータベースの更新に依存します。

**商用サービスに組み込めますか。**

コードは MIT ライセンスです。ただし Deezer と Last.fm の API は非商用利用に限られています。商用利用を考える場合は、各 API の利用規約を確認してください。詳しくは [README のデータの出典](../README.md#データの出典と利用条件) にあります。

**ジャンルの日本語名はどこで決まっていますか。**

`shared/genre/taxonomy.ts` の分類表です。表記ゆれは `shared/genre/normalize.ts` で吸収しています。追加や修正はこの2ファイルで行います。
